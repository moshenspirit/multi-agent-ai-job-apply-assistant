# Boss 直聘智能筛选助手 —— 需求文档

> 版本：v1.0  
> 日期：2026-06-28  
> 状态：需求确认完成

---

## 一、项目概述

### 1.1 项目背景

用户求职过程中，需要在 Boss 直聘上筛选大量岗位，手动浏览效率低下。用户有两份不同方向的简历（前端开发、AI 开发），需要一个智能工具辅助完成岗位采集、匹配分析、结果呈现，最终由人工决定投递。

### 1.2 项目目标

打造一个**半自动化的岗位筛选助手**：
- 自动采集 Boss 直聘岗位信息
- 基于 LLM 智能判断岗位与两份简历的匹配度
- 生成结构化筛选报告
- 人工审核后手动投递（不触碰 Boss 平台交互红线）

### 1.3 核心原则

| 原则 | 说明 |
|------|------|
| **半自动化** | 程序仅做信息采集和智能分析，不对 Boss 直聘执行任何"投递""沟通"等交互操作 |
| **红线意识** | 不自动登录、不自动点击沟通按钮、不自动发送简历，避免封号风险 |
| **人工兜底** | 最终投递决策和操作完全由用户手动完成 |

|------|------|

## 三、功能需求

### 3.1 简历管理

**3.1.1 多简历上传与管理**

- 支持上传 PDF 或图片格式的简历文件
- 系统解析简历内容，提取关键信息（技能、经验、项目等）
- 管理两份简历："前端开发"和"AI 开发"
- 支持对解析结果进行人工修正

**3.1.2 简历内容结构化**

- 从简历中提取：技能标签、工作年限、项目经验、教育背景
- 作为后续 LLM 匹配的参考依据

### 3.2 搜索关键词配置

**3.2.1 搜索关键词设置**

系统需要知道在 Boss 直聘上搜什么。支持多组关键词，分别对应不同工作方向：

| 方向 | 搜索关键词（示例） | 对应简历 |
|------|-------------------|----------|
| 前端开发 | 前端开发、React、Vue、Web 前端 | 前端简历 |
| AI 开发 | AI 开发、大模型、AI Agent、机器学习 | AI 简历 |

- 每组关键词支持多个搜索词（系统会分别搜索后合并去重）
- 搜索词可自由增删改

**3.2.2 筛选条件设置（全部支持，权重后期可调）**

| 条件类别 | 具体条件 | 说明 |
|----------|---------|------|
| 地理位置 | 城市/区域（如：广州） | 必须满足 |
| 薪资范围 | 最低薪资 - 最高薪资 | 如 15k-25k |
| 公司规模 | 如 100-499 人、500+ 人等 | 可选 |
| 行业领域 | 互联网、游戏、金融、教育等 | 多选 |
| 学历要求 | 大专/本科/硕士/不限 | 可选 |
| 工作经验 | 1-3 年 / 3-5 年 / 不限 | 可选 |
| 黑名单 | 排除特定公司/关键词 | 可选 |

**3.2.3 条件权重系统**

- 每个筛选条件有可调节的权重（0-10）
- 权重用于岗位列表排序（影响展示顺序，不影响 LLM 匹配打分）
- 岗位排序分 = Σ(各条件满足度 × 权重)
- 权重支持后期灵活调整

### 3.3 岗位采集

**3.3.1 数据采集范围**

- 平台：Boss 直聘
- 采集方式：Playwright 控制浏览器，读取页面内容（不模拟点击交互）
- 采集内容：
  - 岗位名称
  - 公司名称
  - 薪资范围
  - 工作地点
  - 经验/学历要求
  - 职位描述（JD 全文）
  - 公司信息（规模、行业、融资阶段）
  - Boss 活跃度
  - 岗位原始链接（用于人工跳转投递）

**3.3.2 采集策略**

- 数量：先跑通基础流程（约 50-100 条），后续灵活调整
- 翻页：支持多页采集，可配置最大页数或最大采集时间
- 去重：同一岗位不重复采集（以岗位 ID 或 URL 去重）

**3.3.3 频率控制**

- 手动触发执行（用户启动后立即运行）
- 预留定时任务能力（后续可扩展为每日定时）
- 采集过程有合理的请求间隔，避免触发反爬

**3.3.4 异常处理**

- 验证码出现时：暂停采集，通知用户手动处理
- 页面结构变化导致解析失败：记录日志，跳过该条，继续下一条
- 网络超时/反爬拦截：自动重试（最多 3 次），失败后记录并跳过
- 采集异常不中断整体流程，最终报告中标注异常条目

### 3.4 AI 智能匹配

**3.4.1 匹配逻辑**

```
岗位 JD + 用户筛选条件 → LLM 分析 → 输出匹配结果
                                      │
                                      ├── 匹配"前端开发"简历（附匹配度 + 理由）
                                      ├── 匹配"AI 开发"简历（附匹配度 + 理由）
                                      ├── 两者都匹配（附各自匹配度）
                                      └── 都不匹配
```

**3.4.2 LLM 判定标准**

- 输入：岗位 JD 全文 + 两份简历的摘要/关键信息 + 用户筛选条件
- 输出：每份简历的匹配度（0-100）+ 简短理由（1-2 句话）
- 模型：GPT-4o 或同等水平 LLM
- 费用：用户自担

**3.4.3 匹配结果标注**

| 标注 | 含义 |
|------|------|
| 🟢 前端 | 适合前端简历 |
| 🔵 AI | 适合 AI 简历 |
| 🟣 双匹配 | 两份都适合 |
| ⚪ 不匹配 | 都不适合（默认隐藏，可手动查看） |

### 3.5 结果展示

**3.5.1 Web 管理端**

- 一个本地 Web 页面（如 `localhost:3000`）
- 功能页面：
  - **仪表盘**：本次采集概况（总数、匹配数、各方向分布）
  - **岗位列表**：所有匹配的岗位，按匹配度排序
  - **岗位详情**：JD 全文 + 匹配理由
  - **配置中心**：筛选条件设置、简历管理

**3.5.2 岗位列表展示字段**

| 字段 | 说明 |
|------|------|
| 匹配标注 | 前端/AI/双匹配 标签 |
| 匹配度 | 0-100 分 |
| 岗位名称 | - |
| 公司名称 | - |
| 薪资 | - |
| 地点 | - |
| 经验/学历 | - |
| 原始链接 | Boss 直聘岗位直达链接（方便人工跳转投递） |
| 匹配理由 | LLM 给出的简短理由 |
| 状态 | 新岗位 / 已查看 / 已投递 |

**3.5.3 操作功能**

- 查看岗位详情
- 手动标记"已投递"（记录投递状态）
- 按匹配方向/匹配度/薪资等筛选排序
- 导出筛选结果（Markdown/Excel）

### 3.6 投递记录管理

- 记录已标记"已投递"的岗位
- 后续采集自动排除已投递的岗位（去重）
- 支持查看投递历史

## 四、非功能需求

### 4.1 运行环境

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10 |
| 浏览器 | Chromium（Playwright 内置） |
| Python 版本 | ≥ 3.10 |
| 网络 | 需要科学上网（LLM API 调用） |

### 4.2 性能要求

- 单次采集 50-100 个岗位，整体耗时 < 10 分钟（含 LLM 分析）
- Web 页面响应流畅

### 4.3 可扩展性

- 配置入口采用 Web 页面，便于后期增加功能
- 筛选条件权重系统预留可调节空间
- 预留定时任务能力（后续可扩展每日自动运行）
- 预留完全自动化能力（但当前不实现，仅留接口）

### 4.4 安全要求

- 不自动执行 Boss 直聘的登录、沟通、投递操作
- 不存储用户账号密码
- 简历文件本地存储，不上传第三方
- LLM API Key 本地配置

## 五、用户使用流程

```
┌──────────────────────────────────────────────────────┐
│  初次使用                                              │
│  ① 打开 Web 管理端                                     │
│  ② 上传两份简历（PDF/图片）                             │
│  ③ 配置筛选条件（地点、薪资、方向等）                     │
│  ④ 设置条件权重                                        │
└──────────────────┬───────────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────────┐
│  日常使用                                              │
│  ⑤ 点击"开始采集"                                      │
│  ⑥ 系统自动：搜索 → 采集 → LLM 分析 → 生成报告          │
│  ⑦ 在 Web 页面查看筛选结果                              │
│  ⑧ 人工判断，选出想投的岗位                              │
│  ⑨ 手动打开 Boss 直聘，找到对应岗位，投递                │
│  ⑩ 回到系统，标记"已投递"                               │
└──────────────────────────────────────────────────────┘
```

## 六、术语定义

| 术语 | 定义 |
|------|------|
| JD | Job Description，职位描述 |
| 匹配度 | LLM 对岗位与简历契合程度的评分（0-100） |
| 双匹配 | 一个岗位同时匹配两份简历 |
| 去重 | 已投递或已采集过的岗位不再重复出现 |
