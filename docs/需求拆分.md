# 需求拆分 —— 开发任务清单

> 根据《需求文档 v1.0》拆分，按优先级和依赖关系排列

---

## 拆分总览

```
需求1：项目基础设施        ← 先做，所有模块的底座
需求2：简历管理模块        ← 独立模块
需求3：条件配置模块        ← 独立模块（含搜索关键词 + 筛选条件）
需求4：岗位采集模块        ← 核心模块，依赖需求1+需求3
需求5：AI 智能匹配模块     ← 核心模块，依赖需求2+需求3+需求4
需求6：结果展示模块        ← 前端模块，依赖需求5
需求7：投递记录模块        ← 依赖需求4+需求6
```

---

## 需求 1：项目基础设施

**目标**：搭建项目骨架，让所有模块能运行起来

| 编号 | 任务 | 说明 |
|------|------|------|
| 1.1 | 初始化 Python 项目 | 虚拟环境、requirements.txt、目录结构 |
| 1.2 | 搭建 FastAPI 后端框架 | 基础路由、CORS、启动脚本 |
| 1.3 | 搭建 React 前端框架 | Vite + React + 路由，对接后端 |
| 1.4 | 设计并创建 SQLite 数据库 | 定义表结构：岗位表、简历表、配置表、投递记录表 |
| 1.5 | 环境配置管理 | .env 文件管理（API Key、数据库路径等） |

**产出物**：能跑起来的空壳项目，前后端联通

---

## 需求 2：简历管理模块

**目标**：上传、解析、管理两份简历

| 编号 | 任务 | 说明 |
|------|------|------|
| 2.1 | 简历上传接口（后端） | 接收 PDF/图片文件，存储到本地 |
| 2.2 | PDF 简历解析 | PyMuPDF 提取文本内容 |
| 2.3 | 图片简历解析 | OCR 识别（PaddleOCR / Tesseract） |
| 2.4 | 简历信息结构化 | 用 LLM 从解析文本中提取：技能、经验、项目、教育 |
| 2.5 | 简历管理接口 | CRUD：创建、查看、编辑、删除简历 |
| 2.6 | 简历管理页面（前端） | 上传、查看解析结果、手动编辑 |

**产出物**：能上传简历 → 自动解析 → 查看/编辑结构化信息

---

## 需求 3：条件配置模块

**目标**：用户可配置搜索关键词、筛选条件及权重

| 编号 | 任务 | 说明 |
|------|------|------|
| 3.1 | 配置数据模型 | 定义搜索关键词组 + 筛选条件字段 + 权重字段 |
| 3.2 | 配置 CRUD 接口 | 保存、读取、更新配置 |
| 3.3 | 搜索关键词配置（前端） | 多组关键词管理，每组对应一个简历方向 |
| 3.4 | 筛选条件配置页面（前端） | 表单界面：地点、薪资、公司规模等 + 权重滑块 |
| 3.5 | 配置校验 | 前端 + 后端校验（薪资范围合理性、关键词非空等） |

**产出物**：能在 Web 页面配置搜索关键词 + 所有筛选条件并保存

---

## 需求 4：岗位采集模块

**目标**：根据配置的搜索关键词，从 Boss 直聘采集岗位信息

| 编号 | 任务 | 说明 |
|------|------|------|
| 4.1 | Playwright 环境搭建 | 安装浏览器驱动，基础启动/关闭 |
| 4.2 | Boss 直聘页面分析 | 分析搜索页 DOM 结构、职位列表选择器、详情页结构 |
| 4.3 | 搜索页列表采集 | 根据配置的搜索关键词搜索，采集职位列表（名称、公司、薪资、地点、链接） |
| 4.4 | 职位详情页采集 | 进入详情页采集 JD 全文、公司信息、原始链接 |
| 4.5 | 多关键词合并去重 | 多组关键词搜索结果合并，按岗位 URL/ID 去重 |
| 4.6 | 翻页采集 | 支持多页翻页，可配置最大页数 |
| 4.7 | 反爬策略 | 随机延迟、请求间隔、User-Agent 轮换 |
| 4.8 | 异常处理 | 验证码通知、解析失败跳过、超时重试、日志记录 |
| 4.9 | 采集任务接口 | 触发采集 → 返回进度 → 存入数据库 |
| 4.10 | 采集状态页面（前端） | 显示采集进度、本次采集概况 |

**产出物**：点击"开始采集"→ 按关键词搜索 → 自动翻页抓取 → 合并去重 → 岗位数据入库

---

## 需求 5：AI 智能匹配模块

**目标**：用 LLM 判断岗位与两份简历的匹配度（结合用户筛选条件）

| 编号 | 任务 | 说明 |
|------|------|------|
| 5.1 | LLM 调用封装 | 封装 OpenAI API 调用，支持重试、超时 |
| 5.2 | 匹配 Prompt 设计 | 设计 system prompt + 结构化输出格式（输入含 JD + 简历 + 筛选条件） |
| 5.3 | 批量匹配逻辑 | 遍历新采集的岗位，逐个调用 LLM 分析 |
| 5.4 | 匹配结果存储 | 匹配度 + 匹配方向 + 理由 存入数据库 |
| 5.5 | 并发控制 | 控制 LLM 并发请求数，避免限流 |
| 5.6 | 费用统计 | 记录每次调用的 token 消耗，统计费用 |

**产出物**：岗位采集完成后自动执行匹配，每个岗位标注匹配方向和分数

---

## 需求 6：结果展示模块

**目标**：Web 页面展示筛选结果，支持查看和筛选

| 编号 | 任务 | 说明 |
|------|------|------|
| 6.1 | 仪表盘页面（前端） | 本次采集概况：总数、各方向匹配数、分布图 |
| 6.2 | 岗位列表接口（后端） | 分页、筛选、排序 |
| 6.3 | 岗位列表页面（前端） | 卡片/表格展示，匹配标注、匹配度、关键信息 |
| 6.4 | 岗位详情页面（前端） | JD 全文 + 匹配理由 + 公司信息 |
| 6.5 | 列表筛选排序（前端） | 按方向、匹配度、薪资筛选和排序 |
| 6.6 | 导出功能 | 导出筛选结果为 Markdown/Excel |

**产出物**：完整的 Web 管理界面，可查看、筛选、排序岗位

---

## 需求 7：投递记录模块

**目标**：管理投递状态，自动去重

| 编号 | 任务 | 说明 |
|------|------|------|
| 7.1 | 投递状态更新接口 | 标记岗位为"已投递" |
| 7.2 | 投递历史接口 | 查询已投递记录 |
| 7.3 | 采集去重联动 | 新采集时自动排除已投递岗位 |
| 7.4 | 投递历史页面（前端） | 查看投递历史列表 |

**产出物**：标记投递 → 记录历史 → 下次采集自动排除

## 推荐开发顺序

```
第一轮：需求1 → 需求2 → 需求3
        （基础 + 简历 + 配置，先把能填数据的部分做了）

第二轮：需求4
        （采集模块，核心难点，独立攻克）

第三轮：需求5
        （AI 匹配，依赖简历和岗位数据就位）

第四轮：需求6 → 需求7
        （前端展示 + 投递管理，收尾）
```
