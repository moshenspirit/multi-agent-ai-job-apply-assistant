## 一、工作流架构（业务流程）

### 1.1 完整工作流

```
┌─────────────────────────────────────────────────────────────────┐
│                         【初次配置】                               │
│                                                                   │
│  上传简历 ──→ 简历解析 ──→ 结构化存储                              │
│                                                                   │
│  配置搜索关键词 ──→ 配置筛选条件 ──→ 设置权重 ──→ 保存配置          │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│                         【日常使用】                               │
│                                                                   │
│  ① 点击"开始采集"                                                 │
│       │                                                           │
│       ▼                                                           │
│  ② 读取配置（搜索关键词）                                         │
│       │                                                           │
│       ▼                                                           │
│  ③ 遍历关键词组，逐个搜索                                          │
│       │                                                           │
│       ▼                                                           │
│  ④ 采集列表页 → 翻页 → 采集详情页                                  │
│       │                                                           │
│       ▼                                                           │
│  ⑤ 合并去重（跨关键词 + 历史已投递）                                │
│       │                                                           │
│       ▼                                                           │
│  ⑥ 存入数据库（状态=新采集）                                       │
│       │                                                           │
│       ▼                                                           │
│  ⑦ 批量 LLM 匹配分析                                              │
│       │  对每个岗位：JD + 简历 + 筛选条件 → 匹配度 + 方向 + 理由    │
│       │                                                           │
│       ▼                                                           │
│  ⑧ 匹配结果写入数据库                                              │
│       │                                                           │
│       ▼                                                           │
│  ⑨ 按筛选条件过滤 + 权重排序                                        │
│       │                                                           │
│       ▼                                                           │
│  ⑩ 生成结果报告（Web 页面展示）                                     │
│                                                                   │
│  ─────────────────────────────────────────                        │
│                                                                   │
│  ⑪ 用户查看结果                                                   │
│  ⑫ 手动打开 Boss 直聘投递                                          │
│  ⑬ 回到系统标记"已投递"                                            │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 状态流转

```
岗位在系统中的生命周期：

  [新采集] ──→ [LLM匹配完成] ──→ [已查看] ──→ [已投递]
                                        │
                                        └──→ [不感兴趣]（隐藏）
```

### 1.3 采集任务的错误处理流程

```
遍历关键词搜索
  │
  ├── 成功 → 采集列表 → 翻页 → 采集详情 → 入库
  │
  ├── 验证码 → 暂停采集 → Web 前端弹窗通知 → 用户处理 → 继续
  │
  ├── 页面结构变化 → 记录日志 → 跳过 → 继续下一条
  │
  ├── 网络超时 → 重试(最多3次) → 仍失败 → 记录 → 跳过
  │
  └── 全部完成后 → 汇总报告（含异常条目数）
```

### 2.2 技术选型及理由

| 层级 | 技术 | 版本 | 理由 |
|------|------|------|------|
| **前端框架** | Vue 3 | 3.4+ | 上手快，模板语法直观，中文文档好，生态够用 |
| **构建工具** | Vite | 5+ | Vue 官方推荐，HMR 极快 |
| **UI 样式** | Tailwind CSS | 3+ | 快速出界面，不用手写 CSS |
| **前端路由** | Vue Router | 4+ | Vue 官方路由方案 |
| **状态管理** | Pinia | 2+ | Vue 官方推荐，比 Vuex 更简洁 |
| **HTTP 客户端** | Axios | - | 前端请求后端 |
| **后端框架** | Flask | 3.0+ | 轻量灵活，同步模式更匹配 Playwright 同步 API |
| **ORM** | SQLAlchemy | 2.0+ | Python 标准 ORM，配合 SQLite |
| **数据库** | SQLite | - | 单机本地运行，零配置，够用 |
| **异步任务** | threading + Flask | - | 采集任务在独立线程执行，进度通过 SSE 推送 |
| **实时推送** | SSE (Server-Sent Events) | - | 采集进度实时推前端，Flask 通过 generator 实现 |
| **浏览器自动化** | Playwright (Python) | 1.40+ | 同步 API 与 Flask 天然匹配，反检测好 |
| **AI 接口** | OpenAI Python SDK | 1.0+ | 直接调 GPT-4o，也兼容其他 LLM 的 OpenAI 兼容接口 |
| **PDF 解析** | PyMuPDF (fitz) | - | 轻量，提取文本效果好 |
| **图片 OCR** | PaddleOCR | - | 离线可用，中文识别好，不花钱 |
| **项目管理** | pip + venv | - | 依赖管理 |

### 2.4 数据库设计

```sql
-- 简历表
CREATE TABLE resumes (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT NOT NULL,              -- 简历名称（如"前端开发"）
    direction   TEXT NOT NULL,              -- 方向（frontend / ai）
    file_path   TEXT,                       -- 原始文件路径
    raw_text    TEXT,                       -- 解析出的原始文本
    structured  TEXT,                       -- 结构化信息（JSON）
    -- structured 示例：
    -- {
    --   "skills": ["React", "TypeScript", "Vue"],
    --   "years": 3,
    --   "education": "本科",
    --   "projects": [...]
    -- }
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 配置表（单例，只有一条记录）
CREATE TABLE config (
    id                  INTEGER PRIMARY KEY CHECK (id = 1),
    search_keywords     TEXT NOT NULL,       -- 搜索关键词组（JSON）
    -- search_keywords 示例：
    -- [
    --   {"direction": "frontend", "keywords": ["前端开发", "React", "Vue"]},
    --   {"direction": "ai", "keywords": ["AI开发", "大模型", "AI Agent"]}
    -- ]
    filter_conditions   TEXT NOT NULL,       -- 筛选条件（JSON）
    -- filter_conditions 示例：
    -- {
    --   "city": "广州",
    --   "salary_min": 15000,
    --   "salary_max": 25000,
    --   "company_size": ["100-499", "500+"],
    --   "industry": ["互联网", "游戏"],
    --   "education": "本科",
    --   "experience": "1-3年",
    --   "blacklist": ["某公司", "关键词"]
    -- }
    weights             TEXT NOT NULL,       -- 权重配置（JSON）
    -- weights 示例：
    -- {"salary": 8, "location": 10, "company_size": 5, ...}
    max_pages           INTEGER DEFAULT 5,   -- 最大翻页数
    max_collect_time    INTEGER DEFAULT 600, -- 最大采集时间（秒）
    updated_at          TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 岗位表
CREATE TABLE jobs (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    job_name        TEXT NOT NULL,           -- 岗位名称
    company_name    TEXT NOT NULL,           -- 公司名称
    salary_min      INTEGER,                -- 最低薪资
    salary_max      INTEGER,                -- 最高薪资
    city            TEXT,                   -- 工作城市
    district        TEXT,                   -- 区域
    experience      TEXT,                   -- 经验要求
    education       TEXT,                   -- 学历要求
    jd_text         TEXT,                   -- 职位描述全文
    company_size    TEXT,                   -- 公司规模
    company_industry TEXT,                  -- 公司行业
    company_finance TEXT,                   -- 融资阶段
    boss_active     TEXT,                   -- Boss 活跃度
    source_url      TEXT NOT NULL UNIQUE,   -- Boss 直聘原始链接（去重键）
    source_keyword  TEXT,                   -- 来源搜索关键词
    -- 匹配结果
    match_direction TEXT,                   -- 匹配方向：frontend / ai / both / none
    match_score_frontend INTEGER,           -- 前端匹配度 0-100
    match_score_ai    INTEGER,              -- AI 匹配度 0-100
    match_reason      TEXT,                 -- 匹配理由
    -- 状态
    status          TEXT DEFAULT 'new',     -- new / viewed / applied / ignored
    collect_batch   TEXT,                   -- 采集批次标识
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 投递记录表
CREATE TABLE delivery_records (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    job_id      INTEGER NOT NULL,           -- 关联岗位 ID
    status      TEXT DEFAULT 'applied',     -- applied / interviewed / offer / rejected
    note        TEXT,                       -- 备注
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (job_id) REFERENCES jobs(id)
);
```

### 3.2 各模块职责

#### M1: 仪表盘
- 显示本次/最近一次采集概况
- 匹配分布统计（前端/AI/双匹配/不匹配 数量）
- "开始采集"按钮 + 采集进度条
- 采集状态实时更新（SSE）

#### M2: 岗位列表
- 卡片式列表展示岗位
- 筛选：按匹配方向、匹配度范围、薪资范围
- 排序：按匹配度、薪资、时间
- 批量标记操作
- 导出按钮

#### M3: 岗位详情
- JD 全文展示
- 公司详细信息
- 匹配度 + 匹配理由
- 原始链接（点击跳转 Boss 直聘）
- 状态操作（已投递 / 不感兴趣）

#### M4: 配置中心
- 搜索关键词管理（增删改）
- 筛选条件表单
- 权重滑块
- 采集参数（最大页数等）

#### M5: 简历管理
- 上传区域（拖拽 PDF/图片）
- 解析结果展示
- 手动编辑结构化信息

#### M6: 投递历史
- 已投递岗位列表
- 按时间排序
- 查看详情

#### S1: 采集服务
- 接收采集指令 → 读取配置 → 遍历关键词
- 每个关键词：打开搜索页 → 采集列表 → 进入详情 → 翻页
- 采集过程中通过 SSE 推送进度
- 异常情况按 1.3 流程处理

#### S2: 匹配服务
- 读取新采集的岗位（状态=new）
- 批量调用 LLM：JD + 简历摘要 + 筛选条件 → 匹配结果
- 结果写入 jobs 表
- 统计 token 消耗

#### S3: 简历解析
- PDF：PyMuPDF 提取文本
- 图片：PaddleOCR 识别
- 文本清洗后调用 LLM 结构化提取

## 四、关键技术决策

### 4.1 为什么采集和匹配要分开？

采集和匹配是两个独立步骤，**不串行**：

```
错误做法：搜一个 → 采集一个 → 匹配一个 → 搜下一个
正确做法：全部搜完采集完 → 统一批量匹配
```

理由：
- 采集和 LLM 匹配的耗时特征不同（采集 IO 密集，匹配 API 调用密集）
- 分开后可以独立优化（如采集完成后用户可以暂停匹配、调整参数再跑）
- 中间结果落库，不怕中断

### 4.2 为什么用 SSE 而不是 WebSocket？

采集任务执行时间较长（几分钟），前端需要实时看到进度。SSE 比 WebSocket 更适合：
- 单向推送（服务端 → 前端），不需要双向通信
- Flask 通过 generator + Response 实现，简单可靠
- 浏览器自动重连

### 4.3 如何避免 Boss 直聘反爬？

```
策略分层：
┌─────────────────────────────┐
│ 第1层：身份伪装              │
│ · 使用真实 Chromium 浏览器   │
│ · Playwright stealth 补丁   │
│ · 不修改 navigator 属性     │
├─────────────────────────────┤
│ 第2层：行为拟人              │
│ · 操作间随机延迟 2-5 秒     │
│ · 翻页间隔 5-10 秒          │
│ · 鼠标移动轨迹模拟（可选）    │
├─────────────────────────────┤
│ 第3层：流量控制              │
│ · 单次采集不超过 100 个岗位  │
│ · 每天最多执行 1 次          │
│ · 不高频重复搜索同一关键词   │
├─────────────────────────────┤
│ 第4层：异常降级              │
│ · 遇到验证码 → 暂停通知用户  │
│ · 页面变化 → 跳过不崩溃     │
│ · 全程日志记录便于排查       │
└─────────────────────────────┘
```

## 六、后续扩展预留

| 扩展点 | 预留方式 |
|------|---------|
| 定时任务 | config 表预留 `schedule_enabled`、`schedule_time` 字段 |
| 完全自动化 | services 层预留 `apply()` 方法接口（空实现） |
| 多平台 | collector 使用策略模式，可扩展为 `BossCollector`、`LagouCollector` |
| 多 LLM | llm_client 封装为抽象接口，支持切换 OpenAI / Claude / 本地模型 |
| 通知推送 | 预留 `notify()` 方法接口 |
