## 第10轮（2026-09-03 午休任务）：页面体验 4 项优化 ✅

> 用户午睡前布置 4 项页面优化 bug + 备份要求。全部独立完成并验证。改动前已完整备份。

### 任务① 岗位列表返回位置保持
- 根因：路由切换销毁组件 + 滚动容器（AppLayout `<main class="overflow-auto">`）scrollTop 重置
- 方案：App.vue router-view 包 `keep-alive include="JobList"`（组件 defineOptions name），缓存实例保留筛选/分页/数据；JobList onDeactivated 记录滚动、onActivated 恢复（main 加 id="page-scroll"）
- 配套：筛选栏加「刷新」按钮（keep-alive 下不自动重拉，新采集点刷新）；onActivated 顺带 reconcileLocal + 刷新黑名单元数据

### 任务② 右键 / 新标签打开岗位
- 根因：卡片是 div @click push，无可右键的链接元素
- 方案：① 卡片标题 a 化（`href=/jobs/:id` + target=_blank）：左键 @click.prevent.stop 走 router.push，**右键/中键保留浏览器原生"新标签打开"**；② 操作行加「新标签打开」按钮；③ 整卡 @auxclick 中键 window.open 新标签
- 新标签打开 = 独立页面实例，原列表不动（位置天然保持）

### 任务③ 已忽略即时消失 + 已查看/未查看分类
- 根因：忽略只改状态不重新筛选，岗位留在当前列表
- 方案：
  - 后端 `list_jobs` / export 支持 `status=viewed,applied` 逗号分隔（in_ 查询，非法值 400，`_parse_statuses` 复用）
  - 列表筛选改 4 段 Tab：**未查看(new，默认)/ 已查看(viewed+applied)/ 已忽略 / 全部**（原状态下拉移除；方向下拉保留，改即时触发）
  - quickStatus 后新状态不属于当前 Tab → 即时本地移除 + total-1（"忽略/投递后消失"）
  - 打开详情自动 `new → viewed`（静默失败不打扰）+ `jobsStore.setLocalStatus` 同步缓存 → 返回列表 reconcileLocal 把不再匹配当前 Tab 的岗位剔除（配合 keep-alive）
  - 空态文案随 Tab 变化（"暂无未查看的岗位"）
  - 列表/导出用 `tabStatusParam()` 保证「已查看」组合参数一致

### 任务④ 公司避雷黑名单 + 重复岗位提示
- 现状：config.filter_conditions.blacklist 数据结构早已存在但**无任何 UI**；matcher 会过滤但已匹配岗位不重算
- 方案：
  - 后端：新增 `GET /api/jobs/company-counts`（按公司聚合岗位数降序）
  - 前端：新建 `stores/company.ts`（blacklist + companyCounts + loadMeta/blacklistHit/countOf/addBlacklist——addBlacklist 先 GET 全量再 merge PUT，避免覆盖其他筛选条件）
  - 列表卡公司行：黑名单命中 → 公司名红色删除线 + 「⚠ 黑名单」红标；同公司在库 >1 岗 → 「同公司 ×N」橙标（批量刷帖预警）
  - 列表/详情操作区：「加入黑名单」按钮（confirm 后一键拉黑，已有则显示"已拉黑"禁用）；详情头部同样展示黑名单/多岗提示
  - 配置中心新增「公司黑名单（避雷）」卡片：tag 列表展示 + 可删 + 输入回车添加，随整体保存
  - 列表 keep-alive 激活时自动刷新元数据，多入口一致
